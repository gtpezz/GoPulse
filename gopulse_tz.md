# Техническое задание (ТЗ)
## Проект: Локальная системная утилита мониторинга «GoPulse»

---

### 1. Общие сведения
**GoPulse** — это кроссплатформенное десктопное приложение для мониторинга ресурсов операционной системы и управления процессами в реальном времени. Приложение является легковесной альтернативой системным диспетчерам задач с возможностью сохранения исторической статистики нагрузки.

---

### 2. Цели и назначение проекта
* **Практическая цель:** Отработка навыков системного программирования на Go, конкурентности (горутины, каналы, тикеры), работы со встраиваемыми БД (SQLite) и интеграции бэкенда с графическим интерфейсом через Wails.
* **Функциональное назначение:** Предоставление пользователю наглядной визуализации состояния ПК (CPU, RAM, Disk, Network), детального списка процессов с возможностью их принудительного завершения, а также аналитики за прошлые периоды.

---

### 3. Технологический стек
* **Язык бэкенда:** Go (версии 1.21+)
* **Desktop-фреймворк:** Wails v3
* **Сбор системных метрик:** `github.com/shirou/gopsutil/v4`
* **База данных:** SQLite (драйвер `modernc.org/sqlite` — Pure Go, не требует CGO)
* **Фронтенд (UI):** React + JavaScript
* **Графики:** Chart.js (или ApexCharts)
* **Стилизация:** TailwindCSS

---

### 4. Архитектура и структура проекта
Приложение собирается в единый исполняемый бинарный файл (экзешник). Взаимодействие между Go и JavaScript-фронтендом осуществляется через механизм генерации биндингов Wails (вызовы функций как Promise) и встроенную шину событий (Events Component).

#### Рекомендуемая структура каталогов:
```text
gopulse/
├── backend/
│   ├── db/          # Инициализация SQLite, миграции, методы записи истории
│   ├── monitor/     # Горутины сборщика метрик (CPU, RAM, Disk, Net)
│   └── process/     # Логика получения списка процессов и их убийства
├── frontend/        # Frontend-приложение (Svelte/React, управляемое Wails)
│   ├── src/
│   │   ├── components/  # Графики, таблицы, кастомные элементы
│   │   └── App.svelte   # Главный интерфейс и табы
├── app.go           # Основной контекст приложения, методы для связи с UI
├── main.go          # Точка входа, конфигурация Wails и системного трея
└── wails.json       # Конфигурация сборки Wails
```

### 5. Функциональные требования

Приложение должно состоять из 3 основных экранов (вкладок): **Дашборд**, **Диспетчер процессов**, **История**.

#### 5.1. Экран «Дашборд» (Мониторинг в реальном времени)
* **Частота обновления:** Строго 1 раз в секунду (`time.Ticker`).
* **Отображаемые метрики:**
    * **CPU:** Общая загрузка в % (круговой или линейный live-график), текущая тактовая частота, количество потоков/процессов.
    * **RAM:** Всего доступно, использовано (в ГБ), процент занятости. Live-график изменения за последние 60 секунд.
    * **Disk:** Список дисков/разделов, объем (Свободно/Всего), текущая скорость чтения/записи (Кб/с или Мб/с).
    * **Network:** Текущая скорость отдачи (Upload) и скачивания (Download).
* **Реализация:** Фоновая горутина опрашивает пакет `gopsutil` и пушит JSON-структуру в UI через `wails.Events.Emit("metrics_update", data)`.

#### 5.2. Экран «Диспетчер процессов»
* **Отображение:** Таблица со списком всех запущенных в ОС процессов.
* **Колонки таблицы:** PID, Имя процесса, Потребление CPU (%), Потребление памяти (МБ).
* **Функционал управления:**
    * Поиск/фильтрация по имени процесса (ввод в текстовое поле).
    * Сортировка по любой из колонок (по клику на заголовок). Сортировка должна выполняться эффективно.
    * Кнопка **«Завершить процесс» (Kill)** напротив каждого процесса. По клику фронтенд вызывает Go-метод `KillProcess(pid)`.
* **Безопасность:** Обработка ошибок при попытке завершить системный процесс (вывод Toast-уведомления "Доступ запрещен" или "Процесс не найден").

#### 5.3. Экран «История» (Аналитика)
* **Агрегация данных:** Каждую секунду писать данные на диск нельзя. Бэкенд должен аккумулировать секундные метрики в памяти, высчитывать **среднее значение за 1 минуту** и делать одну запись (INSERT) в SQLite.
* **Интерфейс:** Возможность выбрать период (За последний час, За 24 часа, За неделю).
* **Визуализация:** Статический график, отображающий тренд загрузки CPU и RAM за выбранный период на основе исторических данных из локального файла БД.

#### 5.4. Системные фичи (Tray & UX)
* **Работа в фоне:** Кнопка закрытия окна приложения `[X]` должна не завершать процесс, а прятать окно в системный трей (Tray Icon).
* **Иконка трея:** Динамическое отображение текущего процента загрузки CPU прямо на маленькой иконке в трее (опционально, либо просто статичная иконка с контекстным меню "Открыть / Выйти").
* **Тема оформления:** Наличие переключателя Dark / Light Mode.

### 6. Схема базы данных (SQLite)

Локальная база данных `gopulse.db` создается автоматически при первом запуске в папке приложения или в системной директории AppData.

```sql
CREATE TABLE IF NOT EXISTS system_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
    cpu_usage_avg REAL,      -- Средний % за минуту
    ram_usage_avg REAL,      -- Средний % за минуту
    net_download_bytes INTEGER, -- Суммарный трафик за минуту
    net_upload_bytes INTEGER
);
```

---

### 7. Нефункциональные требования
* **Потребление ресурсов:** Само приложение GoPulse не должно нагружать процессор более чем на 1-2% в режиме мониторинга и не должно течь по памяти (ограничение до 50-70 МБ RAM).
* **Кроссплатформенность:** Код должен без изменений компилироваться под Windows 10/11 и Linux (Ubuntu/Debian). Ограничения по специфичным для конкретной ОС вызовам `gopsutil` должны быть обработаны через конструкции `runtime.GOOS` или build tags, если потребуется.
* **Интерфейс:** Отсутствие рывков при отрисовке live-графиков (плавная анимация сдвига точек влево).

### 8. План разработки (Этапы)
1. **Этап 1 (Бэкенд):** Написание CLI-прототипа на Go. Подключение `gopsutil`, вывод в консоль метрик каждую секунду через `time.Ticker`. Написание функции `KillProcess` и проверка её работы.
2. **Этап 2 (Инициализация Wails):** Создание каркаса приложения через `wails init`. Настройка проброса данных из горутины в шину событий.
3. **Этап 3 (Фронтенд дашборда):** Верстка главного экрана, подключение Chart.js, подписка на событие обновлений, рендеринг "живых" графиков.
4. **Этап 4 (Процессы):** Реализация таблицы процессов, добавление сортировки, фильтрации и связывание кнопки "Убить" с бэкендом.
5. **Этап 5 (База данных):** Подключение SQLite, написание воркера агрегации данных (1 точка в минуту). Создание экрана истории.
6. **Этап 6 (Полировка):** Добавление иконки в трей, настройка сворачивания, оптимизация потребления ресурсов, сборка финального `.exe` / бинарника.
